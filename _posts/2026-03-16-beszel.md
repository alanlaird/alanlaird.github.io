Most homelab monitoring stacks end up becoming a project on their own — install Prometheus,
configure exporters, set up Grafana, design dashboards, write alert rules. That's a
real stack and it's worth it at scale and super valuable to have at home to keep your 
skills fresh. But sometimes you just want something simple that is always working. 

[Beszel](https://beszel.dev) is a lightweight monitoring dashboard that covers the basics
fast. Hub is one Docker container. Agent is a single Go binary on each host. No Prometheus,
no YAML scrape configs, no exporter port soup. Add a system and you're watching its metrics
in under a minute.

## The hub + agent pattern

[![Beszel architecture diagram showing hub on sixes connecting to six KVM hosts](/img/beszel-arch.svg)](https://beszel.dev)

Beszel uses a hub-and-agent model:

- **Hub** runs as a Docker container on a management host. It serves the web UI, stores
  historical data, and SSH-tunnels out to each agent to collect metrics.
- **Agent** is a static Go binary that runs on each host you want to monitor. It listens
  on port 45876 and waits for the hub to connect. Optionally, it can auto-register itself
  with the hub on startup using a token — so new hosts show up in the UI without any
  manual add step.

Container stats (Docker or Podman) are optional: pass `DOCKER_HOST` and the agent will
introspect the socket. Nothing else to configure.

## The Ansible roles

My homelab has six KVM hosts running Alpine Linux plus a Debian host. The Ansible setup
is two task files: one for the hub and one for the agent. The hub runs on `sixes`. The
agent task supports both Alpine (OpenRC) and Debian (systemd) from the same file.

### Hub — `roles/common/tasks/beszel_hub.yml`

The hub is a docker-compose one-shot. No config file, no secrets beyond the compose itself:

```yaml
- name: Create beszel hub data directory
  ansible.builtin.file:
    path: /data/beszel/beszel_data
    state: directory
    owner: root
    group: root
    mode: '0755'

- name: Deploy beszel hub docker-compose.yml
  ansible.builtin.copy:
    dest: /data/beszel/docker-compose.yml
    mode: '0644'
    content: |
      services:
        beszel:
          image: henrygd/beszel
          container_name: beszel
          restart: unless-stopped
          ports:
            - 8090:8090
          volumes:
            - /data/beszel/beszel_data:/beszel_data
  notify: restart beszel

- name: Start beszel hub
  ansible.builtin.command:
    cmd: docker compose up -d --remove-orphans
    chdir: /data/beszel
  register: compose_result
  changed_when: "'Started' in compose_result.stdout or 'Created' in compose_result.stdout"
```

Running `ansible-playbook nodes/sixes.yml` and the hub is live at `http://sixes:8090`
within seconds:

![ansible-playbook terminal output showing hub up in 4 seconds](/img/beszel-terminal.svg)

First run: open the UI, create an admin account. From Settings, copy the hub's public
key into `beszel_hub_key` in your inventory, and generate a universal token
(Settings → Tokens) into `beszel_hub_token`.

### Agent — `roles/common/tasks/beszel_agent.yml`

The agent task downloads a versioned binary, writes the hub's public key to a file,
deploys a service config (OpenRC on Alpine, systemd on Debian), and enables the service.

#### Two credentials, two jobs

Before looking at the task, it's worth clarifying what each credential does:

- **Hub SSH public key** (`beszel_hub_key`) — required. Written to `/etc/beszel/hub_key`
  and loaded via the `KEY_FILE` env var. The hub uses this to authenticate its connection
  to the agent.
- **Universal token** (`beszel_hub_token`) — for auto-registration. The agent sends this
  to the hub on startup so the host appears in the UI automatically. The Beszel docs say
  you can "use a universal token to connect" — it means registration, not auth. The SSH
  key is still required.

Writing the key to a file rather than passing it via `--key` avoids quoting problems:
the key string (`ssh-ed25519 AAAA...`) contains a space that breaks argument parsing in
both systemd's `EnvironmentFile` expansion and shell-based init scripts.

#### The task

```yaml
- name: Create /etc/beszel config dir
  ansible.builtin.file:
    path: /etc/beszel
    state: directory
    mode: '0750'

- name: Write hub public key file
  ansible.builtin.copy:
    dest: /etc/beszel/hub_key
    content: "{{ beszel_hub_key }}\n"
    mode: '0640'
  notify: restart beszel-agent

- name: Check installed beszel-agent version
  ansible.builtin.command: /usr/local/bin/beszel-agent --version
  register: beszel_agent_installed
  changed_when: false
  failed_when: false

- name: Download and extract beszel-agent
  ansible.builtin.get_url:
    url: "https://github.com/henrygd/beszel/releases/download/v{{ _ver }}/beszel-agent_linux_amd64.tar.gz"
    dest: "/tmp/beszel-agent-{{ _ver }}.tar.gz"
  vars:
    _ver: "{{ beszel_agent_version | default('0.18.4') }}"
  when: (_ver) not in (beszel_agent_installed.stdout | default(''))
  # followed by tar extract to /usr/local/bin

# Alpine / OpenRC
- name: Write beszel-agent conf.d (Alpine)
  ansible.builtin.copy:
    dest: /etc/conf.d/beszel-agent
    mode: '0640'
    content: |
      KEY_FILE=/etc/beszel/hub_key
      TOKEN="{{ beszel_hub_token }}"
      URL="{{ beszel_hub_url }}"
      PORT="{{ beszel_agent_port | default('45876') }}"
      DOCKER_HOST="{{ beszel_docker_host | default('') }}"
  when: ansible_facts['os_family'] == 'Alpine'
  notify: restart beszel-agent

- name: Write beszel-agent OpenRC init (Alpine)
  ansible.builtin.copy:
    dest: /etc/init.d/beszel-agent
    mode: '0755'
    content: |
      #!/sbin/openrc-run
      name="beszel-agent"
      command="/usr/local/bin/beszel-agent"
      command_background=true
      pidfile="/run/${RC_SVCNAME}.pid"
      output_log="/var/log/beszel-agent.log"
      error_log="/var/log/beszel-agent.log"
      start_pre() {
        . /etc/conf.d/beszel-agent
        export KEY_FILE
        command_args="--listen ${PORT:-45876} --token ${TOKEN} --url ${URL}"
        [ -n "${DOCKER_HOST}" ] && export DOCKER_HOST
      }
  when: ansible_facts['os_family'] == 'Alpine'
  notify: restart beszel-agent

# Debian / systemd
- name: Write beszel-agent env file (Debian)
  ansible.builtin.copy:
    dest: /etc/beszel/agent.env
    mode: '0640'
    content: |
      KEY_FILE=/etc/beszel/hub_key
      TOKEN={{ beszel_hub_token }}
      URL={{ beszel_hub_url }}
      LISTEN={{ beszel_agent_port | default('45876') }}
      DOCKER_HOST={{ beszel_docker_host | default('') }}
  when: ansible_facts['os_family'] == 'Debian'
  notify: restart beszel-agent

- name: Write beszel-agent systemd unit (Debian)
  ansible.builtin.copy:
    dest: /etc/systemd/system/beszel-agent.service
    content: |
      [Unit]
      Description=Beszel monitoring agent
      After=network.target

      [Service]
      EnvironmentFile=/etc/beszel/agent.env
      ExecStart=/usr/local/bin/beszel-agent --listen $LISTEN --token $TOKEN --url $URL
      Restart=always
      RestartSec=5

      [Install]
      WantedBy=multi-user.target
  when: ansible_facts['os_family'] == 'Debian'
  notify:
    - reload systemd
    - restart beszel-agent

- name: Enable and start beszel-agent
  ansible.builtin.service:
    name: beszel-agent
    state: started
    enabled: true
```

`ansible.builtin.service` works for both — Ansible handles the OpenRC vs systemd
abstraction automatically.

### Why not just `apk add beszel-agent`?

`beszel-agent` and `beszel-agent-openrc` are in Alpine's edge/community repo. Three
reasons to skip it:

1. **The upstream init script doesn't support `KEY_FILE`, `TOKEN`, `HUB_URL`, or
   `DOCKER_HOST`** — only `KEY` and `LISTEN`. You'd patch the init anyway.
2. **Version pinning.** Alpine edge packages update on their own schedule. Pinning
   `beszel_agent_version` keeps every host on the same known-good binary.
3. **Cross-distro.** The same task file deploys to Alpine and Debian. The APK package
   only helps on Alpine.

### Wiring it into node playbooks

Shared vars live in `group_vars/all/main.yml`:

```yaml
beszel_hub_key: "ssh-ed25519 AAAA..."   # hub Settings page
beszel_hub_token: "your-token"           # hub Settings → Tokens
beszel_hub_url: "http://sixes:8090"
```

Each node playbook adds the agent task and sets any host-specific overrides:

```yaml
# nodes/arago.yml (excerpt)
vars:
  beszel_docker_host: "unix:///run/podman/podman.sock"
tasks:
  - name: Setup beszel agent
    ansible.builtin.include_role:
      name: common
      tasks_from: beszel_agent
```

First run takes about 30 seconds per host (binary download + service setup). Subsequent
runs are idempotent no-ops unless the version changes.

## Podman: the Docker socket problem

All my KVM hosts run Podman rather than Docker. Out of the box, Beszel's agent looks for
containers at `/var/run/docker.sock`. On a Podman host, that socket doesn't exist — so
the agent starts fine but shows no container stats and no error.

Podman's socket lives at `/run/podman/podman.sock` (root) or
`/run/user/<uid>/podman/podman.sock` (rootless). Podman does expose a Docker-compatible
API on that socket — Beszel works against it fine — but it won't look there unless you
tell it to.

One tempting fix is a symlink:

```sh
ln -s /run/podman/podman.sock /var/run/docker.sock
```

My podman Ansible task does exactly this, for `lazydocker` compatibility:

```yaml
- name: Podman socket for lazydocker
  ansible.builtin.file:
    src: /var/run/podman/podman.sock
    dest: /var/run/docker.sock
    state: link
```

The problem: `/var/run` is a tmpfs on most Linux distros, so the symlink disappears on
reboot. The Podman socket itself also only exists after the `podman` service starts. If
Beszel agent starts before Podman, it sees no socket and silently skips container
monitoring for the rest of the session.

The clean fix is to set `DOCKER_HOST` in the agent's environment so it points directly
at the Podman socket regardless of what's at the Docker default path:

```yaml
# in your node playbook vars
beszel_docker_host: "unix:///run/podman/podman.sock"
```

The agent conf.d writes that as an environment variable:

```
DOCKER_HOST="unix:///run/podman/podman.sock"
```

The OpenRC init script exports it conditionally — only if set, so the same task file
works on Docker hosts too:

```sh
start_pre() {
  . /etc/conf.d/beszel-agent
  export KEY_FILE
  command_args="--listen ${PORT:-45876} --token ${TOKEN} --url ${URL}"
  [ -n "${DOCKER_HOST}" ] && export DOCKER_HOST
}
```

On Debian, `DOCKER_HOST` in `/etc/beszel/agent.env` is picked up automatically by
systemd's `EnvironmentFile` — no special handling needed in the unit file.

This survives reboots, works whether or not a Docker symlink exists, and the same role
deploys to both Docker and Podman hosts. Container names, CPU, memory, and network I/O
show up in the hub UI alongside host metrics.

## Variables reference

| Variable | Default | Description |
|---|---|---|
| `beszel_hub_key` | required | Hub SSH public key — written to `/etc/beszel/hub_key` |
| `beszel_hub_token` | required | Universal token for auto-registration |
| `beszel_hub_url` | required | Hub URL (e.g. `http://sixes:8090`) |
| `beszel_agent_port` | `45876` | Port the agent listens on |
| `beszel_agent_version` | `0.18.4` | Agent binary version to install |
| `beszel_docker_host` | `""` | Container socket — Podman or Docker (optional) |

## Why this works well for a homelab

Beszel doesn't try to replace Prometheus. It stores its own data, handles its own
retention, and doesn't need a time-series database or a scrape config ecosystem. For
a homelab where you mostly want to answer "is anything melting, out of disk, or running
away with RAM?" — it nails that in about fifteen minutes of setup and a handful of
Ansible tasks.

Beszel also monitors containers.  I love being able to see a single page of all my containers to see if any are running hot and burning a ton of resources.
