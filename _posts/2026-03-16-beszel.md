# Homelab monitoring in 15 minutes with Beszel and Ansible

Most homelab monitoring stacks end up becoming a project on their own — install Prometheus,
configure exporters, set up Grafana, design dashboards, write alert rules. That's a
real stack and it's worth it at scale. But sometimes you just want to know whether your
six Intel N5105 boxes are overheating or running out of RAM without a three-hour yak shave.

[Beszel](https://beszel.dev) is a lightweight monitoring dashboard that covers the basics
fast. Hub is one Docker container. Agent is a single Go binary on each host. No Prometheus,
no YAML scrape configs, no exporter port soup. Add a system and you're watching its metrics
in under a minute.

## The hub + agent pattern

[![Beszel architecture diagram showing hub on myrtle connecting to six KVM hosts](/img/beszel-arch.svg)](https://beszel.dev)

Beszel uses a hub-and-agent model:

- **Hub** runs as a Docker container on a management host. It serves the web UI, stores
  historical data, and SSH-tunnels out to each agent to collect metrics.
- **Agent** is a static Go binary that runs on each host you want to monitor. It listens
  on port 45876 and waits for the hub to connect. Optionally, it can auto-register itself
  with the hub on startup using a token — so new hosts show up in the UI without any
  manual add step.

Container stats (Docker or Podman) are optional: pass `DOCKER_HOST` and the agent will
introspect the socket. Nothing else to configure.

## The Ansible roles

My homelab has six KVM hosts, all running Alpine Linux. The Ansible setup is two task
files: one for the hub and one for the agent. The hub runs on `myrtle` (management box).
All six KVM hosts run the agent.

### Hub — `roles/common/tasks/beszel_hub.yml`

The hub is a docker-compose one-shot. No config file, no secrets beyond the compose itself:

```yaml
- name: Create beszel hub data directory
  ansible.builtin.file:
    path: /data/beszel/beszel_data
    state: directory
    owner: root
    group: root
    mode: '0755'

- name: Deploy beszel hub docker-compose.yml
  ansible.builtin.copy:
    dest: /data/beszel/docker-compose.yml
    mode: '0644'
    content: |
      services:
        beszel:
          image: henrygd/beszel
          container_name: beszel
          restart: unless-stopped
          ports:
            - 8090:8090
          volumes:
            - /data/beszel/beszel_data:/beszel_data
  notify: restart beszel

- name: Start beszel hub
  ansible.builtin.command:
    cmd: docker compose up -d --remove-orphans
    chdir: /data/beszel
  register: compose_result
  changed_when: "'Started' in compose_result.stdout or 'Created' in compose_result.stdout"
```

Running `ansible-playbook nodes/myrtle.yml` and the hub is live at `http://myrtle:8090`
within seconds:

![ansible-playbook terminal output showing hub up in 4 seconds](/img/beszel-terminal.svg)

First run: open the UI, create an admin account, copy the hub's public key from Settings.
That key goes into your Ansible inventory as `beszel_hub_key`. Optionally generate a
universal token under Settings → Systems for agent auto-registration.

### Agent — `roles/common/tasks/beszel_agent.yml`

The agent task downloads a versioned binary, writes an OpenRC init script, and enables
the service. It skips the download if the right version is already installed:

```yaml
- name: Check installed beszel-agent version
  ansible.builtin.command: /usr/local/bin/beszel-agent --version
  register: beszel_agent_installed
  changed_when: false
  failed_when: false

- name: Download beszel-agent
  ansible.builtin.get_url:
    url: "https://github.com/henrygd/beszel/releases/download/v{{ _beszel_agent_version }}/beszel-agent_linux_amd64.tar.gz"
    dest: "/tmp/beszel-agent-{{ _beszel_agent_version }}.tar.gz"
    mode: '0644'
  vars:
    _beszel_agent_version: "{{ beszel_agent_version | default('0.18.4') }}"
  when: (_beszel_agent_version) not in (beszel_agent_installed.stdout | default(''))

- name: Extract beszel-agent binary
  ansible.builtin.command:
    cmd: >
      tar -xzf /tmp/beszel-agent-{{ _beszel_agent_version }}.tar.gz
      -C /usr/local/bin beszel-agent
  vars:
    _beszel_agent_version: "{{ beszel_agent_version | default('0.18.4') }}"
  when: (_beszel_agent_version) not in (beszel_agent_installed.stdout | default(''))
  notify: restart beszel-agent

- name: Write beszel-agent conf.d
  ansible.builtin.copy:
    dest: /etc/conf.d/beszel-agent
    mode: '0640'
    content: |
      KEY="{{ beszel_hub_key }}"
      TOKEN="{{ beszel_hub_token | default('') }}"
      HUB_URL="{{ beszel_hub_url | default('') }}"
      PORT="{{ beszel_agent_port | default('45876') }}"
      DOCKER_HOST="{{ beszel_docker_host | default('') }}"
  notify: restart beszel-agent

- name: Write beszel-agent OpenRC init script
  ansible.builtin.copy:
    dest: /etc/init.d/beszel-agent
    mode: '0755'
    content: |
      #!/sbin/openrc-run
      name="beszel-agent"
      description="Beszel monitoring agent"
      command="/usr/local/bin/beszel-agent"
      command_background=true
      pidfile="/run/${RC_SVCNAME}.pid"
      output_log="/var/log/beszel-agent.log"
      error_log="/var/log/beszel-agent.log"
      start_pre() {
        . /etc/conf.d/beszel-agent
        command_args="--key \"${KEY}\" --listen ${PORT:-45876}"
        [ -n "${TOKEN}" ] && command_args="${command_args} --token ${TOKEN}"
        [ -n "${HUB_URL}" ] && command_args="${command_args} --url ${HUB_URL}"
        [ -n "${DOCKER_HOST}" ] && export DOCKER_HOST
      }
  notify: restart beszel-agent

- name: Enable and start beszel-agent
  ansible.builtin.service:
    name: beszel-agent
    state: started
    enabled: true
```

The `KEY` is required — it's the hub's SSH public key, used to authenticate the hub's
tunnel connection. `TOKEN` + `HUB_URL` are optional but convenient: the agent reaches out
to the hub on startup and registers itself, so the host appears in the UI automatically
rather than needing to be manually added.

### Wiring it into node playbooks

Each KVM host playbook includes the agent task at the end. The Podman socket is passed
via `beszel_docker_host` so the agent can also show container-level stats:

```yaml
# nodes/arago.yml (excerpt)
- name: Setup beszel agent
  hosts: arago
  remote_user: root
  vars:
    ansible_ssh_private_key_file: ~/Sync/.ssh/alpine
    beszel_hub_key: "ssh-ed25519 AAAA..."          # from hub Settings page
    beszel_hub_token: "your-universal-token"        # from hub Settings → Systems
    beszel_hub_url: "http://myrtle:8090"
    beszel_docker_host: "unix:///run/podman/podman.sock"
  tasks:
    - name: Setup beszel agent
      ansible.builtin.include_role:
        name: common
        tasks_from: beszel_agent
```

All agents install, register with the hub, and appear in the dashboard. First run takes
about 30 seconds per host (binary download + service setup). Subsequent runs are idempotent
no-ops unless the version changes.

## Podman: the Docker socket problem

All my KVM hosts run Podman rather than Docker. Out of the box, Beszel's agent looks for
containers at `/var/run/docker.sock`. On a Podman host, that socket doesn't exist — so
the agent starts fine but shows no container stats and no error.

Podman's socket lives at `/run/podman/podman.sock` (root) or
`/run/user/<uid>/podman/podman.sock` (rootless). Podman does expose a Docker-compatible
API on that socket — Beszel works against it fine — but it won't look there unless you
tell it to.

One tempting fix is a symlink:

```sh
ln -s /run/podman/podman.sock /var/run/docker.sock
```

My podman Ansible task does exactly this, for `lazydocker` compatibility:

```yaml
- name: Podman socket for lazydocker
  ansible.builtin.file:
    src: /var/run/podman/podman.sock
    dest: /var/run/docker.sock
    state: link
```

The problem: `/var/run` is a tmpfs on most Linux distros, so the symlink disappears on
reboot. The Podman socket itself also only exists after the `podman` service starts. If
Beszel agent starts before Podman, it sees no socket and silently skips container
monitoring for the rest of the session.

The clean fix is to set `DOCKER_HOST` in the agent's environment so it points directly
at the Podman socket regardless of what's at the Docker default path:

```yaml
# in your node playbook vars
beszel_docker_host: "unix:///run/podman/podman.sock"
```

The agent conf.d writes that as an environment variable:

```
DOCKER_HOST="unix:///run/podman/podman.sock"
```

And the OpenRC init script exports it conditionally — only if set, so the same task file
works on Docker hosts too:

```sh
start_pre() {
  . /etc/conf.d/beszel-agent
  command_args="--key \"${KEY}\" --listen ${PORT:-45876}"
  [ -n "${TOKEN}" ]       && command_args="${command_args} --token ${TOKEN}"
  [ -n "${HUB_URL}" ]     && command_args="${command_args} --url ${HUB_URL}"
  [ -n "${DOCKER_HOST}" ] && export DOCKER_HOST
}
```

This survives reboots, works whether or not a Docker symlink exists, and the same role
deploys to both Docker and Podman hosts. Container names, CPU, memory, and network I/O
show up in the hub UI alongside host metrics.

## Variables reference

| Variable | Default | Description |
|---|---|---|
| `beszel_hub_key` | required | SSH public key from hub Settings |
| `beszel_hub_token` | `""` | Universal token for auto-registration |
| `beszel_hub_url` | `""` | Hub URL (e.g. `http://myrtle:8090`) |
| `beszel_agent_port` | `45876` | Port the agent listens on |
| `beszel_agent_version` | `0.18.4` | Agent binary version |
| `beszel_docker_host` | `""` | Container socket path (Docker or Podman) |

## Why this works well for a homelab

Beszel doesn't try to replace Prometheus. It stores its own data, handles its own
retention, and doesn't need a time-series database or a scrape config ecosystem. For
a homelab where you mostly want to answer "is anything melting, out of disk, or running
away with RAM?" — it nails that in about fifteen minutes of setup and a handful of
Ansible tasks.

The source for the Ansible roles is in [ansible-homelab](https://github.com/alanlaird/ansible-homelab).
